# tg-saved — обвязка корпуса Telegram

Инструменты извлечения, распознавания и подготовки материалов, из которых собирается вики
(хранилище — `<корень проекта>/wiki`, мастер источников — `<корень проекта>/raw`).

**Здесь только код.** Источники и расшифровки живут не тут: отобранные материалы уезжают в мастер вики,
рабочие выгрузки экземпляра остаются в `<корень проекта>/_tools/tg-saved/export/` и в git не попадают.

Код mechanism-only лежит в вендоренной копии `<корень проекта>/_toolkit/tools/tg-saved`. Локальные данные
экземпляра остаются в `_tools/tg-saved`; mechanism не создаёт и не поставляет их.

## Перед выгрузкой

- Перечисли источники до выгрузки: какие чаты и папки идут в работу, что пропущено и почему.
- Проверь малым срезом: прогони полный путь на нескольких сообщениях, прежде чем гнать весь архив.
- Секреты выгрузки (ключи и токены) — только в локальном окружении машины, в репозиторий не коммитятся.

## Прокси

Если Telegram и часть внешних адресов доступны только через прокси, задайте его адрес и порт сам: `--proxy
http://host:port` или переменной `TG_PROXY`. Умолчания в коде нет — порт у каждой машины свой, без параметра
подключение идёт напрямую.

## Окружение

Для расшифровки используй отдельное проектное окружение `.venv-asr` с `faster-whisper` и `onnx-asr`.
Корневой `.venv` оставлен для клиента Telegram (`_toolkit/tools/tg-saved/tg_saved.py`) и содержит
`telethon` + `python-socks`; ASR-скрипты запускаются именно через `.venv-asr`.

Пути передавай нативными (`<буква>:/путь/к/проекту/...`): путь оболочки (`/f/...`) нативный интерпретатор
не понимает. Скрипты говорят об этом прямо — «путь не найден», а не «аудио не найдено».

Восстановление ASR-окружения с нуля:

```bash
cd <корень проекта>
uv venv .venv-asr --python 3.14
uv pip install --python .venv-asr/Scripts/python.exe faster-whisper onnx-asr
```

`ffmpeg` и `ffprobe` должны быть в `PATH`. Веса GigaAM: `_tools/tg-saved/models/gigaam` (224,9 МБ,
ONNX int8) — в git не попадают и не должны.

**Пути к данным — свои у каждой машины.** Выгрузка Telegram Desktop и приёмник пайплайна agrowiki задаются
параметрами (`--base`, `--export`, `--dest`) и обязательны: без них скрипт падает с внятным сообщением, а не
подставляет чужой путь. В коде этих путей нет.

## Где описан подход

- Навык `telegram-archive-pipeline` — полная процедура: выгрузка, проверка чекбоксов медиа, выбор движка
  по длине записи, правило двух моделей, правила фьюзинга R1–R8, ловушки (обрыв GigaAM на длинном входе,
  кириллизация латиницы моделью `small`, филлеры).
- `<корень проекта>/_toolkit/links-playbook.md` — забор внешних ссылок.
- `<корень проекта>/_toolkit/images-playbook.md` — распознавание изображений.

## Замечание о копиях

Часть скриптов продублирована в навыке `telegram-archive-pipeline` (`scripts/`) — это снимки для
переносимости. Канон — здесь; перед запуском вложенной копии сверяйте хеши (однострочник есть в навыке).
История болезни: копии расходились молча, в навыке лежала версия без таблицы терминов и без исправления
таксономии.
