# Плейбук забора ссылок

Порядок работы с внешними ссылками корпуса: чем пробовать, в каком порядке, как фиксировать результат и что остаётся человеку. Документ появился после того, как знание о лайфхаках оказалось размазано по докстрингам трёх скриптов и разделу «как это читать» в списке упрямых, то есть его нельзя было прочитать целиком.

Общее правило: **«не снято» без указания способа и причины недействительно.** Упрямость бывает трёх видов, и лечится по-разному:

| вид упрямости | признак | лечение |
|---|---|---|
| инструментом | страница есть, но отдаётся не тем запросом | сменить способ забора (таблица ниже) |
| временем | отказ из-за лимита параллельных задач, а не блокировки | пауза между запросами и повторный проход |
| человеком | содержимое недоступно ничем машинным | владелец или другой инструмент (расшифровка видео, вход в аккаунт) |

## Порядок проб

1. **Прямой запрос — только для диагностики.** Он честно показывает, что видит ваша сеть и браузер-эмулятор, но три типовые причины отказа (бот-защита, страница на JavaScript, локальная блокировка сети) он не различает: все три выглядят как «нет ответа» или «200 и 0 байт».
2. **`firecrawl scrape` — основной инструмент.** Ходит со своей стороны, поэтому снимает и бот-защиту, и локальные сетевые блокировки. Ключ берётся из переменной `FIRECRAWL_API_KEY` или из локального `.env` корня проекта, лимит параллельных задач виден в `firecrawl --status`.
3. **Класс отказа определяет вариант вызова:**

| класс отказа | как выглядит | чем брать |
|---|---|---|
| бот-защита | код 403, Cloudflare | `firecrawl scrape --only-main-content -f markdown` |
| страница на JavaScript | код 200, почти пустое тело | то же + `--wait-for 6000` |
| публичный пост Telegram | заглушка «Download Telegram», ~200 байт | адрес с `?embed=1`; обычная страница — каркас |
| страница отдаёт только HTML | firecrawl возвращает пусто, `curl` — сотни килобайт | `curl` → `firecrawl parse <файл> -f markdown` |
| не страница, а файл (изображение, PDF) | URL заканчивается расширением | прямая загрузка `curl -o` — это не работа для скрапера |

4. **Повторный проход обязателен.** При сотне ссылок и лимите в две параллельные задачи часть запросов отваливается сама по себе. Признак — «не снято» там, где класс отказа заведомо излечим. Лечение: `--pause 2` и второй прогон, который пропускает уже сохранённые файлы.
5. **Что не решается скрапингом вовсе:** видео (нужна расшифровка), закрытые аккаунты (нужен вход), домены без серверного содержимого. Это честный список «человеку», а не отказ.

## Инструменты и их роли

- `_toolkit/fetch_links_firecrawl.py` — забор: firecrawl по группам отказа, `?embed=1` для Telegram, пауза и повтор, не перезаписывает уже снятое.
- `_toolkit/finalize_links.py` — реестр `links-fetched.tsv`: по каждой ссылке статус (`снято` / `изображение` / `оболочка` / `не снято`), байты, файл и **способ забора**. Без колонки способа список упрямых невоспроизводим.
- `_toolkit/report_stubborn_links.py` — `stubborn-links.md`: группы по причине отказа, порядок внутри — по решению отбора, с рекомендацией «что делать» для каждой группы.

## Провенанс и учёт

- Снятое складывается в объявленный локальный каталог забора, реестр — `links-fetched.tsv` (шапка: дата, генератор, состав).
- Ссылка, которой нет в реестре, означает «не знаю»; так быть не должно — каждая проблемная ссылка получает статус явно.
- Недоступный источник остаётся в корпусе **с пометкой недоступности и датой последней проверки**, объявленными локальным каноном; на него нельзя опирать утверждения, а карточки, стоящие только на нём, помечаются явно. Исключение источника создаёт ложную чистоту: недоступность — свойство момента, а не источника.
- Числа о заборе (сколько снято, сколько упрямых) берутся из реестра, а не набираются руками: «тринадцать недоступных» в отчёте оказалось рукописным и неверным.

## Грабли, на которые уже наступали

- **Регистр и способ.** Порядок и результат забора фиксируются по каждому адресу; иначе повторный прогон «теряет» уже снятое (у нас три ссылки числились не снятыми, будучи снятыми: сопоставление не узнало домен с концевым дефисом и файл-картинку).
- **Telegram без embed** даёт заглушку, которая выглядит как успех, если проверять только размер файла.
- **Лимит параллельных задач маскируется под блокировку.** «Не снято» после первого прохода — не приговор; сначала повтор с паузой.
- **Картинки и PDF не бывают «страницами».** Скрапер вернёт пусто; файл качается напрямую.
- **Прокси против облака.** Локальный обход (VPN/прокси) помогает браузеру, но не отличает бот-защиту от отсутствия ответа; firecrawl ходит со своей стороны и решает оба случая.
- **Локальный кэш CLI** (`.firecrawl/`) не должен попадать в репозиторий — он в `.gitignore`.
